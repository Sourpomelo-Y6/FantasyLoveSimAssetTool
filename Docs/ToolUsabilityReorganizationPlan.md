# AssetTool 操作整理案

## 目的

現在の Tool は機能追加に合わせてタブが増え、同じ画像を作る作業でも「訓練画像」「画像」「Prompt」など複数のタブを移動する必要がある。
今後は機能の種類ではなく、利用者が完了させたい作業を基準に画面を整理する。

この文書は画面再編の提案であり、既存データ形式や Export 形式を変更するものではない。

## 現在の主な問題

- 訓練画像の枠を作った後、生成には「画像」で対象を選び、「Prompt」で送信する必要がある。
- 外部画像の登録と ComfyUI 生成で入口が異なり、どちらを使えばよいか判断しづらい。
- 「スチル作業」「スチル一覧(確認用)」「画像」「Prompt」の役割が一部重なっている。
- ComfyUI の通常操作と workflow template 編集が同じ場所にあり、日常操作に必要なボタンが埋もれやすい。
- 保存、採用、Export の違いと、現在どこまで完了しているかが画面から分かりづらい。
- ヒロイン、プレイヤー、敵で似た生成操作が別々に実装され、ボタン名や配置が揃っていない。

## 現行実装の操作性診断

現行の `MainWindow` には17個の主タブがあり、利用者が完了させたい作業ではなく、内部機能やデータ種別を基準に画面が分割されている。
このため、1つの素材を完成させるだけでも複数タブを移動し、各画面の保存状態と選択対象を利用者自身で管理する必要がある。

### 頭パーツ画像登録の例

頭パーツの前面・背面画像を登録する場合、現状は次の操作になる。

1. `差分定義` で `AssetId`、`LayerKind`、`DrawOrder` を登録する。
2. `画像` で同じ `AssetId` を再入力し、透過 PNG を `Sprites` 用途として登録する。
3. Status を `Accepted` に変更する。
4. `レイヤープレビュー` で重なりを確認する。
5. `Export` で Unity 用データを出力する。

利用者にとっては「頭パーツ画像を登録する」という1つの作業だが、Tool上では少なくとも4画面に分断される。
さらに、差分定義と画像登録の `AssetId` は文字列の完全一致が必要なため、入力間違いによる未登録・未Exportが発生しやすい。

### 問題の分類

- **情報設計**: `画像`、`スチル作業`、`差分定義`、`服装設定`、`レイヤープレビュー`、`Prompt` の責務が重なり、どこから作業を始めるか判断しづらい。
- **操作フロー**: 定義作成、画像登録、状態変更、確認、Exportが別画面にあり、次に行う操作が画面上で案内されない。
- **用語**: `AssetId`、`LayerKind`、`BackHair`、`HeadExpression`、`FrontAccessory`、`DrawOrder`、`Accepted` など、保存形式の用語が日常操作へ直接露出している。
- **状態管理**: `保存`、`画像登録`、`採用`、`Accepted`、`Export` の違いと、現在どこまで完了しているかを一覧で確認しにくい。
- **操作の不統一**: ヒロイン、敵、プレイヤーで画像登録処理と画面が分かれ、ボタン名や配置が統一されていない。
- **詳細機能の混在**: 日常的な画像制作と、workflow template、定義JSON、Unity同期などの管理機能が同じ階層に並んでいる。
- **保守性**: `MainWindow.xaml` と `MainWindowModel.cs` に多数の機能が集中しており、共通操作の統一や段階的な画面再編が難しい。

### 改善時の判断基準

- 利用者は `AssetId` や `LayerKind` を手入力せず、表示名と画像種別から対象を選べる。
- 一覧で素材を選択した後、画像選択、生成、プレビュー、採用まで同じ画面で完了できる。
- `採用` によって画像登録、Status の `Accepted` 化、Prompt 保存を一括実行する。
- 未保存、未登録、Pending、Accepted、警告あり、Export可能を常に見分けられる。
- 詳細な定義編集と Unity 同期は残すが、通常操作からは折りたたむか別画面へ分離する。

## 第1段階の実装状況

頭パーツ画像を対象に、共通ワークスペースの最小実装として `画像制作` タブを追加した。
既存の `画像` タブは詳細編集用の `画像（詳細）` として残し、既存機能とデータ形式の互換性を維持する。

`画像制作` タブでは次の2種類を日本語名で選択できる。

- `後ろ髪`: `BackHair`、`DrawOrder = 30`
- `顔・表情`: `HeadExpression`、`DrawOrder = 50`

`顔・表情` を選択した場合は、`Neutral`、`Smile`、`Angry` などの表情種類を候補から選択または直接入力する。
表情種類から `HeadExpression_<ExpressionId>` 形式のAssetIdを自動生成するため、同じ画面から複数の表情画像を登録できる。
前髪や前面装飾を独立画像として登録する操作は通常の頭パーツ制作には含めず、必要な場合だけ `差分定義` または `画像（詳細）` で扱う。

各パーツでは透過 PNG を参照またはドラッグ＆ドロップし、`登録して採用` を押す。
この操作でレイヤー定義の作成・更新、`Sprites` 画像登録、Status の `Accepted` 化、定義JSON保存、合成プレビュー更新を一括実行する。
既存の同一 `AssetId` を上書きする場合は確認ダイアログを表示する。

採用前に `テスト表示` を押すと、選択中の未登録PNGと、もう一方の登録済み `Accepted` 頭パーツを合成プレビューへ表示する。
テスト表示では画像コピー、レイヤー定義保存、Status変更を行わない。
テスト結果は `レイヤープレビュー` タブへ渡して表示し、未登録画像を含むことをメッセージと一覧上の `（テスト）` 表記で区別する。
レイヤープレビューの表情候補には、顔画像レイヤーが実際に定義されている表情だけを表示する。初回表示では `Neutral`、衣装は `Default` を優先し、後ろ髪の上へ選択した顔レイヤーを重ねる。
同じ表情IDに旧 `Expression` と新 `HeadExpression` の両方がある場合は `HeadExpression` を優先し、対応する新レイヤーがない場合だけ旧定義へフォールバックする。
レイヤー定義と保存済み画像が存在し、プロフィールのAsset登録だけがない場合は、プレビューに `（未登録）` として重ねる。これは確認専用であり、Export対象にするには画像制作から登録して `Accepted` にする必要がある。
画像制作で採用するときに同名の保存済み画像だけが残っている場合は、確認後にそのファイルを上書き可能として扱い、プロフィールのAsset登録を復旧する。
レイヤープレビューの表示中一覧でレイヤーを選択し、`背面へ` / `前面へ` で描画順を変更できる。変更後は表示中レイヤーの `DrawOrder` を10刻みで再採番し、共通の `Definitions/layer_assets.json` へ即時保存する。

合成プレビューには、実ファイルが存在する `Accepted` 状態の頭パーツだけを `DrawOrder` 順で表示する。
内部の `AssetId`、`LayerKind`、`DrawOrder` は通常操作では折りたたみ、必要な場合だけ確認できる。

## 推奨する全体構成

上部には常に「作業対象」と「現在状態」を表示し、主タブは次の4つに整理する。

1. `キャラクター`
   - ヒロインの選択・作成
   - 基本情報、容姿、口調などの編集
   - プレイヤー、敵の基本情報への入口
2. `画像制作`
   - ヒロインの立ち絵、戦闘、訓練、イベント、行動、エンディング
   - プレイヤー戦闘画像、敵戦闘画像
   - 外部画像登録と ComfyUI 生成
3. `ゲームデータ`
   - 会話、イベント、行動反応、エンディング
   - 表情、衣装、レイヤー定義とプレビュー
4. `確認・Export`
   - 不足素材、保留素材、警告の一覧
   - キャラクター別の制作状況チェック表
   - Export 対象と出力結果

日常的に変更しない `ComfyUI接続設定`、`workflow template`、候補マスタは、通常タブから分離して `設定・詳細` 画面または折りたたみ領域へ移す。

## 画像制作画面の推奨レイアウト

画像制作は、画像種別が違っても同じ操作順になる共通ワークスペースにする。

```text
┌ 対象: TestHeroine / ComfyUI: 接続済み / 未保存: なし ┐
├ 左: 種別・必要画像 ┬ 中央: Prompt・生成操作 ┬ 右: Preview・状態 ┤
│ 訓練             │ 必要条件               │ 現在画像             │
│  training_001     │ positive / negative    │ 生成候補             │
│  BeforeFirst      │ [生成] [停止]          │ Pending / Accepted    │
│  AfterTraining    │ [外部画像を選択]       │ [採用] [却下]         │
└───────────────────────────────────────────────────┘
```

### 左側: 作業対象

- 対象種別を `立ち絵 / 戦闘 / 訓練 / イベント / 行動 / エンディング / プレイヤー / 敵` から選ぶ。
- 必要画像と登録済み画像を同じ一覧に表示する。
- 各行に `未準備 / Prompt準備済み / 生成中 / Pending / Accepted / Rejected / 警告` を表示する。
- 訓練画像では `trainingId`、`visualState`、主人公・ヒロインの表示有無を一覧でも確認できるようにする。
- 「標準15枠を準備」は対象種別を選んだ場所に置き、作成後は最初の未完了枠を自動選択する。初期3訓練の各5状態を共通化せず管理する。

### 中央: 作成方法と生成条件

- 最初に `ComfyUIで生成` と `外部画像を登録` の2つを明示する。
- ComfyUIでは `Prompt編集 → 送信 → 生成待機 → 画像取得` を同じ領域で行う。
- 日常的に使うのは positive、negative、seed、画像サイズ程度とし、model、VAE、LoRA、sampler、workflowは「詳細設定」にまとめる。
- Promptは選択したAssetへ自動保存する。別Assetへ切り替える際、未保存なら確認する。
- ボタン名は全対象で `生成開始 / 生成停止 / 結果を確認 / 画像を取得` に統一する。

### 右側: 確認と採用

- 現在登録中の画像と生成候補を並べて表示する。
- `採用` はAssetへの画像登録、StatusのAccepted化、Prompt記録保存を一括で行う。
- 既存画像を置き換える場合は、対象AssetIdと保存先を確認ダイアログへ表示する。
- `保留` と `却下` を採用の近くに置き、Status変更の結果を即時表示する。
- 解像度、縦横比、透過などの検査結果もPreviewの近くに表示する。

## 推奨する基本操作

### 訓練画像をComfyUIで作る

1. `画像制作` を開き、対象ヒロインと `訓練` を選ぶ。
2. 未作成なら `標準枠を準備` を押す。
3. 左一覧から訓練と表示状態の組み合わせを選ぶ。
4. 中央でPromptを確認し、`生成開始` を押す。
5. 右側で生成候補を確認して `採用` を押す。
6. 次の未完了枠へ移動する。

### 外部で作った画像を登録する

1. `画像制作` で対象の必要画像を選ぶ。
2. `外部画像を登録` を選び、ファイルを指定またはドロップする。
3. Previewと検査結果を確認して `採用` を押す。

どちらの方法でも、最終的に同じ `HeroineAsset`、Prompt JSON、Statusへ保存されるようにする。

## 既存タブの移行対応

| 現在のタブ | 移行先 | 方針 |
|---|---|---|
| 基本情報 | キャラクター | 機能を維持する |
| 画像 | 画像制作 | 登録済み画像一覧と外部登録を統合する |
| 訓練画像 | 画像制作 > 訓練 | 枠準備、マッピング編集、生成を同じ画面に置く |
| 敵キャラ素材 | キャラクター / 画像制作 > 敵 | 基本情報と画像制作を分離する |
| プレイヤー素材 | キャラクター / 画像制作 > プレイヤー | 基本情報と画像制作を分離する |
| スチル作業 | 画像制作 | 共通ワークスペースの基礎として利用する |
| スチル一覧(確認用) | 確認・Export | 不足・状態確認へ統合する |
| Prompt | 画像制作 / 設定・詳細 | 個別Promptは画像制作、workflow編集は詳細へ分ける |
| 会話データ | ゲームデータ | 機能を維持する |
| 差分定義 | ゲームデータ | 表情・衣装・レイヤー定義としてまとめる |
| レイヤープレビュー | ゲームデータ | 差分定義から直接開けるようにする |
| Export | 確認・Export | 警告修正への移動リンクを追加する |

## 状態表示と用語

- `保存`: 入力データをJSONへ保存する。
- `採用`: 画像を対象Assetへ登録し、StatusをAcceptedにする。
- `保留`: 画像や候補を残し、StatusをPendingにする。
- `Export`: AcceptedのデータをUnity取り込み形式へ出力する。

画面上ではこの4語を混同せず、処理完了時に「何を、どこへ保存したか」を表示する。
上部には `未保存あり`、`生成中`、`Export警告あり` を常時表示する。

## 実装順序

### 第1段階: 現行画面の迷いを減らす

- タブ名の近くに目的と次の操作を短く表示する。
- 訓練画像の選択からPrompt/生成対象を自動選択する。
- 全生成画面のボタン名と並び順を統一する。
- workflow template編集を折りたたむ。
- 保存・採用・Exportの説明と状態表示を追加する。

### 第2段階: 画像制作を統合する

- 共通のAsset一覧、Prompt編集、ComfyUI操作、Preview、採用操作を部品化する。
- まず訓練画像と通常のヒロイン画像を統合する。
- 次にスチル、プレイヤー、敵を共通部品へ移す。
- 旧タブは移行中のみ残し、新画面への案内を表示する。

### 第3段階: 確認とExportを統合する

- 不足画像、Pending、検査警告、参照切れを1つの一覧にする。
- 警告行から該当する画像制作・ゲームデータ画面へ移動できるようにする。
- Export前チェックを明示し、問題がなければExportできる構成にする。
- Unity Profile読込後の戦闘メッセージ差分は、結果イベント／パネル文ごとの追加・更新・削除・維持と、話者・表情・表示方式の変更件数を表示し、`戦闘メッセージへ` から編集画面へ移動できるようにする。
- 戦闘後イベントと戦闘パネル結果文は任意のVoice IDも編集・同期する。実音声はToolへ取り込まず、`Resources/Audio/Voice/<HeroineId>/` 以下を指す拡張子なし文字列だけを保持する。

### 音声ライブラリ

音声画面は`BGM・SE`と`VOICE`の独立タブへ分割済み。どちらからUnityプロジェクトを
選択・再走査しても共通設定と結果を使用する。各タブは独立した検索条件と集計を持つ。
`Assets/Resources/Audio` 以下のBGM、SE、VOICEを走査する。固定用途のBGM・SEは
未配置でも期待パスを表示し、VOICEは選択中キャラクターとTool内の訓練・戦闘メッセージ
参照数を表示する。カテゴリ・未配置・検索・キャラクターで絞り込み、導入済みファイルは
Tool上で再生・停止できる。

訓練セリフと戦闘メッセージのVoice IDは、選択中ヒロインで検出した候補から選ぶ
編集可能ComboBoxへ変更済み。内部データとUnity同期JSONは従来どおり拡張子なしIDだけを
保持し、Unityプロジェクトの絶対パスは保存しない。

BGM・SEは一覧の選択行から対応形式のファイルを用途別の正規パスへコピーできる。
既存の同一IDは拡張子が異なる場合も競合として検出し、確認ダイアログで承認した場合だけ
既存ファイルと`.meta`を置き換える。保存先フォルダを開く操作にも対応する。コピーは
明示操作に限定し、音声ファイルとUnity生成`.meta`は現在のテスト素材運用では
Git管理対象にしない。

VOICEの分類・ID指定付き登録も実装済み。選択中ヒロイン、用途、Voice IDから
`Voice/<HeroineId>/<用途>/<VoiceId>`へコピーし、登録のみ、選択中の訓練セリフ、
戦闘後イベント、戦闘パネル結果メッセージへの相対Voice ID設定を選べる。同一用途名の
重複を避け、登録後は一覧を再走査する。

未使用VOICEの確認も実装済み。ファイルあり・Tool参照0件を`△ 未使用`、参照あり・
ファイルなしを`× 未配置`、ファイルと参照ありを`○ 使用中`として区別する。
未使用だけの絞り込み、訓練・戦闘の参照元表示、選択行の保存先表示に対応する。
Unity側の直接参照までは断定できないため、自動削除は行わない。

会話・イベントのVOICE対応も実装済み。通常会話、ゲームイベント、予定イベント、
行動反応、エンディングの各台詞行に任意Voice IDを保持し、編集、Unity読込、Export、
VOICE参照元集計へ反映する。VOICE登録時は選択中の会話・イベント行へ設定でき、
会話・行動反応は`Conversation`、その他イベントは`Event`用途を自動提案する。
Voice ID未設定の既存JSONとの互換性を維持する。

VOICE検証を制作状況画面へ統合済み。選択中キャラクターのVoice IDと走査済みファイルを
照合し、配置済み、未使用、未配置・不正、対象外を`○ / △ / × / ―`で表示する。
詳細行からVOICEタブの該当行へ移動でき、参照数、実ファイル、期待パスを確認できる。
Unityプロジェクト未選択は対象外として案内し、未配置・不正だけをExport準備へ反映する。
未使用VOICEは警告表示するがExportを妨げない。

### キャラクター別制作状況チェック表

機能追加が一通り進んだ段階で、`確認・Export` 内に、選択中または登録済みの各キャラクターについて「何を作成済みで、何が未作成か」を横断確認できるタブページを追加する。

- 行をキャラクター、列を `基本情報 / 立ち絵 / 表情 / 衣装 / 訓練画像 / 訓練セリフ / 会話 / イベント / 戦闘スキル / 戦闘結果メッセージ / スキルツリー / Export準備` などの制作項目とする。
- 必須条件を満たす項目は `○`、未作成または必須不足は `×` で表示する。部分入力、未採用画像、警告がある項目は、必要に応じて `△` として `×` と区別する。
- `○ / △ / ×` にマウスポインターを合わせると、判定理由、登録数と必要数、不足しているIDや枠、警告内容、最終更新情報などをToolTipで表示する。
- セルをクリックすると対象キャラクターを選択したうえで、対応する編集タブ、サブカテゴリ、対象データへ移動し、可能なら不足・警告のある入力欄または一覧行を選択してフォーカスする。
- 項目名のヘッダーにもToolTipを設け、何を満たせば `○` になるかを説明する。
- `未完成のみ表示`、キャラクター絞り込み、項目カテゴリ絞り込みを用意し、全キャラクターが増えても不足箇所を探しやすくする。
- 判定結果そのものは別の正本データとして保存せず、プロフィール、画像Asset、セリフ、スキル、Export検証結果など既存データから共通の判定サービスで都度生成する。
- 項目ごとの完了条件と移動先を定義データとして管理し、機能追加時にチェック表へ列と判定規則を追加しやすくする。
- 任意項目は `×` にせず `―`（対象外・任意）とし、未作成と仕様上不要な状態を区別する。

クリック移動は、各セルが `characterId`、移動先タブ、サブカテゴリ、対象IDを保持する共通ナビゲーション要求を発行する方式を基本とする。各画面が個別に直接参照し合う構成を避け、既存タブを段階的に再編している途中でも移動先を差し替えられるようにする。

`制作状況` タブは現在選択中のキャラクターについて、基本情報、戦闘メッセージ、訓練画像、訓練セリフ、キャラクター画像、会話、イベント、行動反応、表情、衣装、戦闘スキル、スキルツリー、Export準備に対応済み。訓練セリフは登録済み訓練ごとに開始前、進行後、主人公LP消費、ヒロインLP消費、同時LP消費の5状態を必要枠として、枠の有無、重複、本文入り候補を確認する。追加訓練も訓練一覧へ登録すると自動的に5枠が判定対象になる。キャラクター画像は立ち絵、戦闘、イベント、行動、エンディングを用途別に並べ、プロフィールへ登録済み、会話・イベント・戦闘結果から参照中、または基本立ち絵・標準戦闘枠に該当する画像を必須とする。必須画像はAccepted状態と実ファイルを確認し、未参照の定義候補は `―` として未作成と区別する。イベントはゲームイベント・予定イベント・エンディングの有無、空／重複ID、本文、好感度範囲、`once` 用フラグ、表情・衣装・画像・スキル参照を確認する。行動反応は主要行動 `Tea / Rest / Walk / Gift / Talk` の反応有無、空・重複ID、actionId、本文、好感度範囲、優先度、同条件・同優先度の重複、表情・衣装・画像・スキル参照を確認する。Export準備はExportを実行せず、他カテゴリの完成状態、Accepted画像の実ファイル、Export対象件数を読み取り専用で集計する。戦闘スキルは登録件数、空／重複ID、表示名、効果、対象、各数値を確認する。スキルツリーはルート、NodeId、訓練SkillId、前提ノード、付与する戦闘／訓練スキル、解放TrainingIdの参照をノード単位で表示する。カテゴリと各詳細行はクリックすると対応タブへ移動する。`未完成のみ表示` と手動の `再集計` にも対応する。

詳細行には対象種別と対象IDを持たせ、イベントは会話種別と該当行、画像はAsset一覧の該当AssetId、戦闘・訓練スキルとツリーノードは基本情報内の該当行、表情・衣装・レイヤーは定義タブの該当行まで選択する。折りたたまれた戦闘スキル・スキルツリー編集欄へ移動する場合は自動で展開する。

訓練セリフの詳細行は `trainingId` と `visualState` を保持し、訓練画像タブへ移動して対応する訓練Asset、セリフ枠、空本文または先頭候補を選択する。

キャラクター画像の詳細行は定義済み画像ならスチル作業タブへ移動して用途フィルターとStillDefinitionを選択し、定義外の登録Assetなら画像タブで該当AssetIdを選択する。

行動反応の詳細行は会話データタブを `ActionReactions` へ切り替えて該当行を選択する。主要行動の反応が未作成で対象IDがない場合も、`ActionReactions` 一覧までは移動する。

Export前検証は `ExportValidationService` に共通化し、書き込みを行わず `Error / Warning / Information`、対象種別、対象ID、移動先を返す。制作状況のExport準備と実Exportは同じ結果を利用する。Accepted画像の実ファイル、prompt JSON、会話・イベントのID・本文・条件、表情・衣装・画像・スキル参照、戦闘メッセージ参照を確認する。Errorがある状態でExportを押した場合は件数と影響を確認してから続行し、キャンセルすると制作状況へ移動する。Warningだけの場合は出力を継続し、Export結果へ警告を残す。

## 戦闘メッセージタブ整理計画

2026-08-28に3ページ化と一覧・詳細編集への再構成を完了した。制作状況からの移動は表示名ではなく対象種別とIDで行い、Unity再取込後も選択行をIDで再接続する。戦闘後イベント、パネル結果文、単独帰還反応の各詳細ページには、入力対象と同じ画面で確認できるLocalAI本文候補パネルを追加した。

### 現在の問題

現在の戦闘メッセージタブは、戦闘後イベント、戦闘パネル結果メッセージ、主人公単独外出後の帰還反応という性質の異なる3種類を縦に並べている。3つのDataGridが表示領域を分け合うため各一覧が低く、戦闘後イベントは11列あるため本文と関連設定の同時確認が難しい。単独帰還反応は任意項目だが常時同じ面積を占めている。

### ページ構成

戦闘メッセージタブ内に次の3ページを置く。この3段目タブはデータ種類の切り替えに使い、AI入力欄を本文と別ページへ分離する目的には使わない。

1. `戦闘後イベント`
2. `パネル結果文`
3. `単独帰還反応`

各ページは左側を作業対象一覧、右側を選択項目の詳細編集とする。一覧にはID、結果種別、本文の先頭、Voice IDの有無など、対象を選ぶために必要な列だけを表示する。横スクロールが必要な全項目編集は行わず、値の編集は右側へ集約する。新規追加と削除は一覧見出し付近に明示的なボタンとして置き、どの種類へ追加されるかを明確にする。

### 戦闘後イベントの詳細

右側の詳細欄は次の4セクションへ分ける。セクションは見出しまたは折り畳みを使い、さらに内側のタブは追加しない。

- 基本: `EventId`、結果種別、`BattleContextId`
- セリフ: 話者種別、話者名、本文、Voice ID
- 表示: `StillId`、表示方式、表情ID
- 結果: 好感度変化、解放Outfit ID

本文は複数行の編集不可ではない通常TextBoxとし、Voice ID、StillId、表情ID、衣装IDは現在の候補選択と直接入力を維持する。解放衣装の複数ID入力も既存どおりカンマ区切りを保持する。

### パネル結果文と単独帰還反応

パネル結果文は、左一覧にMessageId、結果種別、本文先頭、Voice ID状態を表示し、右側でMessageId、結果種別、本文、Voice IDを編集する。

単独帰還反応は任意項目であることをページ上部に明示する。左一覧にReactionId、結果種別、BattleContextId、本文先頭を表示し、右側で本文、Voice ID、StillId、表示方式、表情IDまで編集する。未設定ならゲーム側で追加表示しない現在の仕様を維持する。

### 共通操作と状態表示

- Unity取込差分は3ページ共通の折り畳み欄へ置き、通常編集時の高さを占有しない。
- 保存ボタンは戦闘メッセージタブ全体で1つとし、どの内側ページからでも利用できる位置へ置く。
- 各ページに登録件数を表示し、Voice ID未設定は本文不足と区別して参考表示する。
- 将来AI入力補助を追加する場合は、選択中本文と同じ右側のセリフ欄へ折り畳み表示し、AI専用タブは作らない。

### 既存動作を維持する条件

- `profile.json`、FromUnity JSON、Export JSONの形式を変更しない。
- 制作状況の戦闘メッセージ詳細から移動した場合、正しい内側ページと対象行を選択する。
- VOICEタブから戦闘後イベントまたはパネル結果文へVoice IDを設定する既存操作を維持する。
- Unity Profile取込後の追加・更新・削除・維持件数と差分表示を維持する。
- 選択変更、追加、削除、保存、再読み込みで既存値を失わない。
- UI整理とAI生成機能の追加を同時に行わない。

### 実装順

1. 内側3ページと共通フッターを作り、既存DataGridをデータ種類ごとに移動する。
2. 戦闘後イベントを一覧・詳細形式へ変更し、全フィールドの往復を確認する。
3. パネル結果文と単独帰還反応を同じ一覧・詳細形式へ変更する。
4. 制作状況とVOICEタブからの移動・選択処理を内側ページへ対応させる。
5. 選択、追加、削除、保存、再読み込み、ナビゲーションのテストを追加する。

### 完了条件

- 3種類のうち編集中の1種類だけが十分な高さで表示される。
- 戦闘後イベントの本文と全関連設定を横スクロールなしで編集できる。
- 入力対象と将来のAI入力補助が同じページ・詳細欄に収まる。
- 制作状況とVOICEから正しい種類・対象行へ移動できる。
- 保存・再読み込みとUnity同期でデータ内容が変わらない。

## スチル画像登録導線の短縮

### 問題

現在のスチル作業では、対象スチルを選択して画像登録欄へ `AssetId`、用途、状態を反映した後、`画像（詳細）` タブへ移動して画像ファイルを登録する。対象選択と実ファイル登録が別タブに分かれており、スチルを続けて制作・差し替えするとタブ往復が多い。

### 方針

通常のスチル制作はスチル作業タブだけで完結させる。選択中スチルの作業領域へ次の操作と情報を置く。

- `画像を登録・差し替え`: 選択中スチルのAssetIdと用途を使い、画像ファイルを直接登録する。
- 登録済み画像のプレビュー、ファイル名、保存先、AssetStatusを同じ画面に表示する。
- `登録解除`: profileから画像登録を外す。既存仕様どおり画像本体とPrompt JSONは削除しない。
- `画像（詳細）で開く`: AssetId、用途、PromptRecord、状態などを詳しく確認・修正する場合だけ使用する。

画像登録、上書き確認、保存先決定、プレビュー更新は既存の画像（詳細）タブと同じ処理を共用し、保存形式とExport契約は変更しない。スチル作業側に別の登録実装を複製しない。

### 完了条件

- スチルを選択してから画像を登録または差し替えるまで、画像（詳細）タブへ移動する必要がない。
- 登録直後に同じ画面で画像と登録状態を確認できる。
- 登録解除後も画像ファイルとPrompt JSONは残る。
- 必要な場合は選択中Assetを維持したまま画像（詳細）タブへ移動できる。
- 既存の画像登録・上書き・解除・保存再読込の動作が回帰しない。

## 完了条件

- 訓練画像の標準枠作成から採用まで、別タブへ移動せず完了できる。
- 外部画像登録とComfyUI生成が同じAsset一覧を使う。
- 選択中のキャラクター、AssetId、用途、Statusが常に確認できる。
- 保存、採用、Exportの違いが画面内の説明だけで判断できる。
- 通常利用ではworkflow template JSONを表示しなくても作業できる。
- ヒロイン、プレイヤー、敵で生成ボタンの名称と順序が一致する。
- Export警告から修正対象へ直接移動できる。
- キャラクター別制作状況で各項目の完了・不足理由を確認でき、セルから修正対象へ直接移動できる。

## 当面の推奨

第1段階の案内・選択連動・折り畳みと、制作状況から編集対象への移動は実装済み。訓練画像も条件、画像マッピング、画像作成・採用へ整理し、セリフ入力対象とAI補助を同じページに配置した。

全面的な共通部品化は、現時点では通常の次作業にしない。ヒロイン、訓練、プレイヤー、敵の画像制作には異なる入力項目があり、共通化そのものを目的にすると回帰確認が大きくなる。実制作で同じ不具合や操作負担が複数画面に現れた場合に、対象を限定して再検討する。現在の優先順位は [`ProjectStatus.md`](ProjectStatus.md) を参照する。
