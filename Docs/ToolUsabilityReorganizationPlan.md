# AssetTool 操作整理案

## 目的

現在の Tool は機能追加に合わせてタブが増え、同じ画像を作る作業でも「訓練画像」「画像」「Prompt」など複数のタブを移動する必要がある。
今後は機能の種類ではなく、利用者が完了させたい作業を基準に画面を整理する。

この文書は画面再編の提案であり、既存データ形式や Export 形式を変更するものではない。

## 現在の主な問題

- 訓練画像の枠を作った後、生成には「画像」で対象を選び、「Prompt」で送信する必要がある。
- 外部画像の登録と ComfyUI 生成で入口が異なり、どちらを使えばよいか判断しづらい。
- 「スチル作業」「スチル一覧(確認用)」「画像」「Prompt」の役割が一部重なっている。
- ComfyUI の通常操作と workflow template 編集が同じ場所にあり、日常操作に必要なボタンが埋もれやすい。
- 保存、採用、Export の違いと、現在どこまで完了しているかが画面から分かりづらい。
- ヒロイン、プレイヤー、敵で似た生成操作が別々に実装され、ボタン名や配置が揃っていない。

## 推奨する全体構成

上部には常に「作業対象」と「現在状態」を表示し、主タブは次の4つに整理する。

1. `キャラクター`
   - ヒロインの選択・作成
   - 基本情報、容姿、口調などの編集
   - プレイヤー、敵の基本情報への入口
2. `画像制作`
   - ヒロインの立ち絵、戦闘、訓練、イベント、行動、エンディング
   - プレイヤー戦闘画像、敵戦闘画像
   - 外部画像登録と ComfyUI 生成
3. `ゲームデータ`
   - 会話、イベント、行動反応、エンディング
   - 表情、衣装、レイヤー定義とプレビュー
4. `確認・Export`
   - 不足素材、保留素材、警告の一覧
   - キャラクター別の制作状況チェック表
   - Export 対象と出力結果

日常的に変更しない `ComfyUI接続設定`、`workflow template`、候補マスタは、通常タブから分離して `設定・詳細` 画面または折りたたみ領域へ移す。

## 画像制作画面の推奨レイアウト

画像制作は、画像種別が違っても同じ操作順になる共通ワークスペースにする。

```text
┌ 対象: TestHeroine / ComfyUI: 接続済み / 未保存: なし ┐
├ 左: 種別・必要画像 ┬ 中央: Prompt・生成操作 ┬ 右: Preview・状態 ┤
│ 訓練             │ 必要条件               │ 現在画像             │
│  training_001     │ positive / negative    │ 生成候補             │
│  BeforeFirst      │ [生成] [停止]          │ Pending / Accepted    │
│  AfterTraining    │ [外部画像を選択]       │ [採用] [却下]         │
└───────────────────────────────────────────────────┘
```

### 左側: 作業対象

- 対象種別を `立ち絵 / 戦闘 / 訓練 / イベント / 行動 / エンディング / プレイヤー / 敵` から選ぶ。
- 必要画像と登録済み画像を同じ一覧に表示する。
- 各行に `未準備 / Prompt準備済み / 生成中 / Pending / Accepted / Rejected / 警告` を表示する。
- 訓練画像では `trainingId`、`visualState`、主人公・ヒロインの表示有無を一覧でも確認できるようにする。
- 「標準15枠を準備」は対象種別を選んだ場所に置き、作成後は最初の未完了枠を自動選択する。初期3訓練の各5状態を共通化せず管理する。

### 中央: 作成方法と生成条件

- 最初に `ComfyUIで生成` と `外部画像を登録` の2つを明示する。
- ComfyUIでは `Prompt編集 → 送信 → 生成待機 → 画像取得` を同じ領域で行う。
- 日常的に使うのは positive、negative、seed、画像サイズ程度とし、model、VAE、LoRA、sampler、workflowは「詳細設定」にまとめる。
- Promptは選択したAssetへ自動保存する。別Assetへ切り替える際、未保存なら確認する。
- ボタン名は全対象で `生成開始 / 生成停止 / 結果を確認 / 画像を取得` に統一する。

### 右側: 確認と採用

- 現在登録中の画像と生成候補を並べて表示する。
- `採用` はAssetへの画像登録、StatusのAccepted化、Prompt記録保存を一括で行う。
- 既存画像を置き換える場合は、対象AssetIdと保存先を確認ダイアログへ表示する。
- `保留` と `却下` を採用の近くに置き、Status変更の結果を即時表示する。
- 解像度、縦横比、透過などの検査結果もPreviewの近くに表示する。

## 推奨する基本操作

### 訓練画像をComfyUIで作る

1. `画像制作` を開き、対象ヒロインと `訓練` を選ぶ。
2. 未作成なら `標準枠を準備` を押す。
3. 左一覧から訓練と表示状態の組み合わせを選ぶ。
4. 中央でPromptを確認し、`生成開始` を押す。
5. 右側で生成候補を確認して `採用` を押す。
6. 次の未完了枠へ移動する。

### 外部で作った画像を登録する

1. `画像制作` で対象の必要画像を選ぶ。
2. `外部画像を登録` を選び、ファイルを指定またはドロップする。
3. Previewと検査結果を確認して `採用` を押す。

どちらの方法でも、最終的に同じ `HeroineAsset`、Prompt JSON、Statusへ保存されるようにする。

## 既存タブの移行対応

| 現在のタブ | 移行先 | 方針 |
|---|---|---|
| 基本情報 | キャラクター | 機能を維持する |
| 画像 | 画像制作 | 登録済み画像一覧と外部登録を統合する |
| 訓練画像 | 画像制作 > 訓練 | 枠準備、マッピング編集、生成を同じ画面に置く |
| 敵キャラ素材 | キャラクター / 画像制作 > 敵 | 基本情報と画像制作を分離する |
| プレイヤー素材 | キャラクター / 画像制作 > プレイヤー | 基本情報と画像制作を分離する |
| スチル作業 | 画像制作 | 共通ワークスペースの基礎として利用する |
| スチル一覧(確認用) | 確認・Export | 不足・状態確認へ統合する |
| Prompt | 画像制作 / 設定・詳細 | 個別Promptは画像制作、workflow編集は詳細へ分ける |
| 会話データ | ゲームデータ | 機能を維持する |
| 差分定義 | ゲームデータ | 表情・衣装・レイヤー定義としてまとめる |
| レイヤープレビュー | ゲームデータ | 差分定義から直接開けるようにする |
| Export | 確認・Export | 警告修正への移動リンクを追加する |

## 状態表示と用語

- `保存`: 入力データをJSONへ保存する。
- `採用`: 画像を対象Assetへ登録し、StatusをAcceptedにする。
- `保留`: 画像や候補を残し、StatusをPendingにする。
- `Export`: AcceptedのデータをUnity取り込み形式へ出力する。

画面上ではこの4語を混同せず、処理完了時に「何を、どこへ保存したか」を表示する。
上部には `未保存あり`、`生成中`、`Export警告あり` を常時表示する。

## 実装順序

### 第1段階: 現行画面の迷いを減らす

- タブ名の近くに目的と次の操作を短く表示する。
- 訓練画像の選択からPrompt/生成対象を自動選択する。
- 全生成画面のボタン名と並び順を統一する。
- workflow template編集を折りたたむ。
- 保存・採用・Exportの説明と状態表示を追加する。

### 第2段階: 画像制作を統合する

- 共通のAsset一覧、Prompt編集、ComfyUI操作、Preview、採用操作を部品化する。
- まず訓練画像と通常のヒロイン画像を統合する。
- 次にスチル、プレイヤー、敵を共通部品へ移す。
- 旧タブは移行中のみ残し、新画面への案内を表示する。

### 第3段階: 確認とExportを統合する

- 不足画像、Pending、検査警告、参照切れを1つの一覧にする。
- 警告行から該当する画像制作・ゲームデータ画面へ移動できるようにする。
- Export前チェックを明示し、問題がなければExportできる構成にする。
- Unity Profile読込後の戦闘メッセージ差分は、結果イベント／パネル文ごとの追加・更新・削除・維持と、話者・表情・表示方式の変更件数を表示し、`戦闘メッセージへ` から編集画面へ移動できるようにする。

### キャラクター別制作状況チェック表

機能追加が一通り進んだ段階で、`確認・Export` 内に、選択中または登録済みの各キャラクターについて「何を作成済みで、何が未作成か」を横断確認できるタブページを追加する。

- 行をキャラクター、列を `基本情報 / 立ち絵 / 表情 / 衣装 / 訓練画像 / 訓練セリフ / 会話 / イベント / 戦闘スキル / 戦闘結果メッセージ / スキルツリー / Export準備` などの制作項目とする。
- 必須条件を満たす項目は `○`、未作成または必須不足は `×` で表示する。部分入力、未採用画像、警告がある項目は、必要に応じて `△` として `×` と区別する。
- `○ / △ / ×` にマウスポインターを合わせると、判定理由、登録数と必要数、不足しているIDや枠、警告内容、最終更新情報などをToolTipで表示する。
- セルをクリックすると対象キャラクターを選択したうえで、対応する編集タブ、サブカテゴリ、対象データへ移動し、可能なら不足・警告のある入力欄または一覧行を選択してフォーカスする。
- 項目名のヘッダーにもToolTipを設け、何を満たせば `○` になるかを説明する。
- `未完成のみ表示`、キャラクター絞り込み、項目カテゴリ絞り込みを用意し、全キャラクターが増えても不足箇所を探しやすくする。
- 判定結果そのものは別の正本データとして保存せず、プロフィール、画像Asset、セリフ、スキル、Export検証結果など既存データから共通の判定サービスで都度生成する。
- 項目ごとの完了条件と移動先を定義データとして管理し、機能追加時にチェック表へ列と判定規則を追加しやすくする。
- 任意項目は `×` にせず `―`（対象外・任意）とし、未作成と仕様上不要な状態を区別する。

クリック移動は、各セルが `characterId`、移動先タブ、サブカテゴリ、対象IDを保持する共通ナビゲーション要求を発行する方式を基本とする。各画面が個別に直接参照し合う構成を避け、既存タブを段階的に再編している途中でも移動先を差し替えられるようにする。

初期実装として `制作状況` タブを追加し、現在選択中のキャラクターについて基本情報、戦闘メッセージ、訓練画像の3項目に対応済み。基本情報はHeroineId・表示名・性格・口調、戦闘メッセージはソロ／同行の勝敗イベントと勝敗パネル文、訓練画像は登録済み訓練ごとの開始前・進行後・主人公LP消費・ヒロインLP消費・同時LP消費がAcceptedかを個別表示する。カテゴリと各詳細行はクリックすると対応タブへ移動する。`未完成のみ表示` と手動の `再集計` にも対応する。

## 完了条件

- 訓練画像の標準枠作成から採用まで、別タブへ移動せず完了できる。
- 外部画像登録とComfyUI生成が同じAsset一覧を使う。
- 選択中のキャラクター、AssetId、用途、Statusが常に確認できる。
- 保存、採用、Exportの違いが画面内の説明だけで判断できる。
- 通常利用ではworkflow template JSONを表示しなくても作業できる。
- ヒロイン、プレイヤー、敵で生成ボタンの名称と順序が一致する。
- Export警告から修正対象へ直接移動できる。
- キャラクター別制作状況で各項目の完了・不足理由を確認でき、セルから修正対象へ直接移動できる。

## 当面の推奨

全面的な画面再構築を一度に行うと既存機能の回帰確認が大きくなる。
最初は第1段階を実施し、その後「画像制作」共通部品を作って訓練画像から移行する。
訓練画像は必要枠、Prompt、生成、Asset採用の関係が明確なため、共通ワークスペースの最初の適用対象に向いている。
