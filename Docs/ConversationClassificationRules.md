# 通常会話の分類・選択ルール

## 目的

この文書は、AssetToolの `Conversations` とUnityの `ConversationData` で通常会話を追加するときの正本ルールを定める。ゲームイベント、予定イベント、行動反応、エンディングは別データ種別であり、この分類へ混在させない。

## categoryは会話ジャンルとして使う

通常会話の `category` はUnityの `ConversationGenre` へ直接変換されるため、次の4値だけを使う。

| category | 画面表示 | 用途 |
|---|---|---|
| `Daily` | 日常 | 挨拶、生活、雑談、場所に依存しない話題 |
| `Food` | 食べ物 | 料理、食事、飲み物、好みの食べ物 |
| `Adventure` | 冒険 | 探索、戦闘、旅、装備、危険な場所の話題 |
| `Love` | 恋愛 | 好意、二人の関係、将来、親密な話題 |

`LocationTalk`、`WeatherTalk`、`Story`のような独自値は使わない。未知の値はUnity Import時に `Daily` へフォールバックするため、分類ミスを発見しづらくなる。場所、天候、進行段階などの細分類はID、タイトル、条件で表す。

## データ種別の使い分け

| 内容 | 使用する種別 |
|---|---|
| メニューからジャンルを選んで聞く会話 | `Conversations` |
| ゲーム開始、日開始、場所進入、物語進行 | `GameEvents` |
| Tea、Walk、Giftなど行動後の反応 | `ActionReactions` |
| 翌日の予定や自動外出 | `ScheduledEvents` |
| エンディング本文 | `Endings` |

通常会話は「プレイヤーが今このジャンルを選んだときに表示してよい内容」に限定する。発生タイミング自体が意味を持つ文章はイベント側へ置く。

## conversationIdの命名規則

```text
Conv_<Genre>_<Context>_<NN>
```

- `Genre` は `Daily / Food / Adventure / Love`。
- `Context` は内容を表す短いPascalCase。条件が重要なら `Rainy`、`Night`、`HighAffection` などを含める。
- `NN` は同系統内の2桁連番。
- 例: `Conv_Daily_Greeting_01`、`Conv_Food_Tea_02`、`Conv_Love_RainyNight_01`。
- IDは表示済み管理とセーブデータで使うため、本番公開後は変更しない。
- ヒロインIDは保存フォルダで分離されるため、通常はconversationIdへ含めない。

## 現在利用できる条件

Unityの通常会話選択で現在利用される条件は次のとおり。

- `minAffection` / `maxAffection`: 0から9999。両端を含む。
- `costumeId`: 空なら衣装不問。
- `timeOfDay`: 空なら時間帯不問。1つの時間帯を指定。
- `season`: 空なら季節不問。1つの季節を指定。
- `weather`: 空なら天候不問。1つの天候を指定。
- `once`: `true`ならconversationIdを表示済みとして保存し、以後候補から除外。

`locationId`、`actionId`、`requiredItemId`、`requiredFlagIds`、`requiredSkillIds` は共通JSON上に存在するが、現状の通常会話Importerと実行時選択には接続されていない。通常会話の必須条件として使わない。場所・進行・スキル条件が必要な内容は、対応済みの `GameEvents` または `ActionReactions` を使う。

## 好感度帯の推奨

好感度は0から9999の整数で管理する。通常会話では細かく分割しすぎず、まず次を目安にする。

| 段階 | 推奨範囲 | 用途 |
|---|---:|---|
| 初期 | 0–199 | 距離がある、基本的な自己紹介 |
| 親しみ | 200–399 | 日常的な雑談 |
| 信頼 | 400–599 | 個人的な話題 |
| 親密 | 600–799 | 好意を含む話題 |
| 深い関係 | 800–9999 | 強い信頼、恋愛、将来の話題 |

境界をまたいで常に使える汎用会話も残す。各ジャンルに少なくとも1件、`0–9999`で他条件なし、`once=false`の会話を用意する。

## priorityの規則

候補は条件一致後、選択スコアが最も高いものから選ばれる。同点候補はランダムで1件選ぶ。基本スコアは `priority` で、当日の予定によりジャンル別に最大10程度の補正が加算される。

| priority | 用途 |
|---:|---|
| `0` | 各ジャンルの無条件フォールバック |
| `100` | 通常の条件付き会話 |
| `200` | 季節、天候、時間帯、衣装に強く対応する会話 |
| `300` | 高好感度または一度だけの重要会話 |
| `400`以上 | 明示的に最優先したい特殊会話。多用しない |

予定補正で意図せず順位が逆転しないよう、意味の異なる優先段階は20以上離す。同じ条件とpriorityで複数用意することは、ランダムな会話差分を意図する場合だけ許可する。

## 選択順とフォールバック

Unityは次の順で通常会話を選ぶ。

1. プレイヤーが選んだ `ConversationGenre` と一致する候補を集める。
2. 好感度、衣装、時間帯、季節、天候を満たさない候補を除外する。
3. `showOnce`かつ表示済みの候補を除外する。
4. `priority`へ当日の予定によるジャンル補正を加え、最高スコアを求める。
5. 最高スコアが同じ候補からランダムに1件選ぶ。

候補が0件の場合、別ジャンルや条件なし会話を自動検索せず、「現在の条件に合う会話データがありません」と表示する。そのため、各ジャンルに無条件フォールバックを最低1件置く。フォールバックは `priority=0`、`once=false`、好感度 `0–9999`、衣装・時間帯・季節・天候を空にする。

## onceの扱い

- 自己紹介、関係進展、秘密の告白など、一度だけで意味がある会話に限定する。
- `once=true`ではconversationIdを必須とする。
- 日常的な会話やジャンルのフォールバックには使わない。
- 一度だけ表示した後にも候補が残るよう、同じジャンル・好感度帯へ反復可能な会話を用意する。

## AssetToolでの入力・検証方針

- `Conversations` のcategory候補は4ジャンルに限定する。
- 空または未知のcategory、空・重複ID、空本文、負のpriority、好感度範囲逆転を警告する。
- 各ジャンルの無条件フォールバック有無を確認できるようにする。
- 同じジャンル、条件、priorityの重複は、意図したランダム差分か確認できるようにする。
- 現在未接続の条件を通常会話へ設定した場合は、Unityで選択条件として使われないことを案内する。

## 最小作成単位

最初は各ジャンルについて次を用意する。

1. 無条件フォールバック1件。
2. 好感度帯ごとの会話を必要な段階だけ追加。
3. 季節・天候・時間帯・衣装差分は、通常会話として繰り返し表示してよい内容だけ追加。
4. 一度限りの進行会話は通常会話へ増やさず、GameEventsを優先する。
