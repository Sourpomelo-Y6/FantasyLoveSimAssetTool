# AssetTool 現在状況と作業候補

最終整理日: 2026-08-28

この文書を、プロジェクト横断の「次に何をするか」「何を後回しにしたか」の正本とする。個別計画書は各機能の設計と履歴を保持し、優先順位が競合する場合はこの文書を優先する。

## 現在の状態

- AssetToolの主要なプロフィール、画像、会話・イベント、衣装・表情、スキル、訓練、音声、Export編集機能は実装済み。
- Unityからの主要データ取り込みと、AssetToolからUnity Editor Import用JSONを出力する経路は実装済み。
- LocalAIは接続設定、短文、衣装メッセージ、会話下書き、選択肢・返答、訓練セリフの入力補助に対応済み。
- 訓練画像はUnity訓練一覧の取り込み、固定5状態の画像枠準備、セリフ進捗、未入力絞り込みに対応済み。
- 戦闘メッセージは戦闘後イベント、パネル結果文、単独帰還反応の3ページと一覧・詳細編集に整理済み。各詳細ページ内でLocalAIによる本文3案生成を利用できる。
- 直近のAssetToolテストは218件成功。`net5.0-windows` のサポート終了警告は継続している。

## 現在選択中の次作業

スチル作業タブ内で画像登録・差し替えまで完結できるようにする。現在はスチルを選び、画像登録欄へ値を反映してから `画像（詳細）` タブへ移動して登録する必要があり、通常作業の導線として回りくどい。詳細は [`ToolUsabilityReorganizationPlan.md`](ToolUsabilityReorganizationPlan.md) の「スチル画像登録導線の短縮」を参照する。

## 優先度を決めずに残している作業

次に着手する機能は、実制作で困った箇所を基準にこの一覧から選ぶ。現時点では、どれも自動的な最優先にはしない。

### データ・素材の完成

- TestHeroineの `CooperativeDrill` 固定5状態の訓練画像を用意する。
- DefaultHeroine用の訓練画像データと画像を用意する。
- 各ヒロインの制作状況画面で不足データを確認し、実データを埋める。

画像生成Promptは手動で作成する。AssetToolへ画像Prompt AIを追加する予定はない。

### 動作確認

- Heroine3（クーデリア）で訓練セリフAIの固定5状態を評価する。
- LocalLLMの実出力で話者、LP消費主体、口調、候補差を確認する。
- 実制作で見つかった不具合だけを修正し、評価前に機能を増やさない。

この確認は2026-08-27時点で後回し。手順と記録表は [`Extra/TrainingImagePlan.md`](Extra/TrainingImagePlan.md) に残している。

### 保守・基盤

- 画像ファイル本体とPrompt JSONを削除する操作が本当に必要か判断する。現状の登録解除はファイルを残す。
- 大規模なUI共通部品化は、重複実装が実際の保守負担になった段階で行う。

## 保留

- ヒロイン戦闘スキル・訓練スキルの名前や説明文に対するAI支援。現状の生成品質が十分でないため、通常の作業候補に含めない。
- Heroine3の既存会話から参考台詞を選び、キャラクター固有プロンプトへ追加する機能。
- 長文会話・イベントの一括生成。ローカルLLM向けの入力縮約と分割生成方式を別途設計するまで着手しない。
- 訓練セリフAIの実データ品質評価。必要になった時点で既存の評価表を使用する。
- `net5.0-windows` からサポート中の.NETへの移行。Visual Studio Communityの利用条件と.NET 8に必要な環境は確認済みだが、現時点では移行調査・実装とも行わない。

## 見送った案

- 訓練画像positive promptとnegative promptのAI生成。画像Promptは手動調整する。
- 保存済みプレイヤー選択肢の常時類似警告。短文の誤検出が多いため、生成直後の参考警告だけを維持する。
- AI候補の自動採用・自動保存。人が候補を確認し、通常の保存操作で確定する。
- AIによるAssetId、画像マッピング、訓練条件、好感度変化、イベント構造の決定。
- 音声ファイルの自動削除。Tool外からの参照を断定できないため、確認と手動管理を維持する。

## 次の作業を選ぶ基準

1. 実制作を止めている不具合があれば、その診断と修正を優先する。
2. 不具合がなければ、制作状況画面で不足している実データを埋める。
3. 同じ手作業を何度も繰り返している場合だけ、入力補助や移動操作を追加する。
4. LocalAI機能は、実データ評価で改善点を確認してからプロンプトまたはUIを変更する。
5. 新機能を始める前に、この文書の保留・見送りと矛盾しないか確認する。
